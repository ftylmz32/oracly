**Status:** Canonical · Production readiness — never leave the user confused  
**Version:** 1.0  
**Scope:** Edge cases, loading, errors, empty states, performance, accessibility  
**Hierarchy:** [Master Directive](./MASTER_DIRECTIVE.md) → … → [RC-002 AI Conversation](./RC-002.md) → **RC-003 Resilient Experience** → [RC-007 Craftsmanship](./RC-007.md) → [RC-008 Typography & Reading Comfort](./RC-008.md) → [AI Agent Guide](./AI_AGENT_GUIDE.md)

---

> *A first-time user and a user with poor network should both feel ORACLY is reliable, calm and carefully crafted.*

Do **not** redesign UI. Do **not** add features. Strengthen reliability only.

---

## Mission

Review every user flow for edge cases. The application should never leave the user confused.

---

## Error handling

- Never expose technical messages (`API hatası: 500`, stack traces)
- Simple explanation + recovery action (`Tekrar Dene`)
- Preserve user confidence via `ResilienceCopy`

---

## Loading

- No blank screens — use `OraclySkeletonLoader` or `TarotLoading`
- Intentional calm placeholders, not spinners alone

---

## Empty states

- `OraclyEmptyState` with gentle guidance
- Never feel unfinished

---

## Flow coverage

| Flow | Resilience |
|------|------------|
| Splash | Bootstrap try/catch → safe fallback to shell |
| Chat | `AiMessageResult`, snackbar retry, bootstrap skeleton |
| Oracle | Error snackbar via provider, themed snackbars |
| Card selection | Snackbar on draw failure |
| Memory / History | Skeleton loading + empty states + retry |
| Tarot reading | Existing `TarotErrorState` + session missing copy |

---

## Accessibility

- `Semantics` on retry buttons, send button, loading live regions
- Dynamic text: flexible layouts, no hard truncation of critical copy
