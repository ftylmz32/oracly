## Mission

Prepare ORACLY for long-term personalization by unifying how journey data is stored and queried — without exposing unfinished features.

---

## Journey facets

| Facet | Canonical store | Access |
|-------|-----------------|--------|
| Completed readings | `HistoryRepository` | `IntelligenceRepository.getReadings()` |
| Favorite cards | `ReadingModel.journal.isFavorite` | `getFavoriteCards()` |
| Recurring themes | `PersonalInsightEngine` over readings | `loadSnapshot().journey.insightReport` |
| Personal reflections | Reading notes + ritual thoughts | `getReflections()` |
| AI conversations | `AiConversationRepository` | `getConversations()` |
| Ritual history | Daily ritual date keys | `getRitualHistory()` |

---

## Architecture

```
Canonical stores (existing)
  HistoryRepository ──┐
  AiConversationRepository ──┼──► IntelligenceRepository
  RitualHistoryReader ───────┘         │
                                       ▼
                            IntelligenceLayerService
                                       │
                    Future: Personal Insights · Timeline · Themes · Growth
```

**Rules:**
- AI never writes to the intelligence layer directly
- AI persists through domain repositories (history, ritual, chat)
- Intelligence layer is read-only aggregation + index metadata
- No UI wiring in RC-009
